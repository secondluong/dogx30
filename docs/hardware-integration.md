# RK3588 载荷接入 X30

本文覆盖把 RK3588 开发板装上机器狗并跑通运动控制所需的全部步骤，
以及在动手写后续模块（SLAM、视频）之前必须先在现场问清楚的几件事。

> **2026-08 更新：智能控制器的有无需要重新确认。** 本文原先基于「本机不含
> 智能控制器」写成，但厂家给的拓扑图上画着 `.106`。供电部分的结论不受影响
> （机身仍只有 72V 口），但涉及 `jy_cog` 与 `CustomMsg` 的段落可能作废。
> 上狗当天 `ping 192.168.1.106` 一次即可定论。

前提（待重新确认）：本机 **可能不含智能控制器**。若确实没有，则没有
`192.168.1.106`，官方 `jy_cog` 建图定位套件不可用。无论有无，
机身都不提供 12V/24V 稳压输出。

## 一、供电

机身航插只有一个 **72V / 600W** 电源口（应用手册 §5.2，P1 = 红 = 72V+，P2 = 黑 = GND）。
那些 12V/24V 的 LAN 复合口全在智能控制器上，你们没有。

所以需要自备 **72V→12V DC-DC 降压模块**。选型注意：

- X30 电池标称 72V，充电器输出 84V。降压模块的输入范围要覆盖到 **60–90V** 才安全，
  按 8S~20S 宽压工业模块选。
- NanoPC-T6-Plus 标称 12V 输入，官方推荐适配器 12V/2A 起、满配 12V/4A。
  按 **60W（12V/5A）** 选模块，余量留给 NVMe、相机、云台等外设。
- 板子的容差是 **5–20V**，对降压模块的输出精度要求不高，
  行走时的电源波动也容易扛过去。这比只吃 12V±5% 的板子省心。
- 自行加保险丝，机身侧不提供过流保护。
- 手册未给 72V 口的连接器型号与容差，**装机前找云深处售后确认航插型号与压接规范**，
  不要自己臆测针脚。

**输出接板子的 2Pin 3.5mm 螺丝端子，不要用 5.5×2.1 圆口。**
T6-Plus 两种供电口都有，但圆口 DC 插头在持续振动下有松脱风险，
机器狗一颠就可能瞬断；螺丝端子拧紧了不会松，DC-DC 的输出直接压线接上正好。

## 二、机械安装

- 载荷必须**同时**固定在背部两条导轨上，不能只压一条。
- 载荷高度 ≤ 500mm。
- 总载荷（含所有配件）≤ 20kg，机器人整体 `Payload 20kg`。

NanoPC-T6-Plus 是 **110 × 82.5 mm**，加散热片和外壳后在背部导轨上很宽松，
重量也完全不是问题。

注意板子的工作温度是 **0℃ ~ 70℃**（消费级 SBC 的常见规格，比工控板窄）。
冬季室外作业要考虑保温，或者换工业级方案。

## 三、网络

NanoPC-T6-Plus 有两个 2.5G 网口，正好对上机器狗的两个网段，**不需要外挂交换机**：

| 板子网口 | 接到 | 地址 | 用途 |
| --- | --- | --- | --- |
| eth0 | 机身 Ethernet Port 1 | `192.168.1.120/24` | 运动主机 `.103`、感知主机 `.105` |
| eth1 | 机身 Ethernet Port 2 | `192.168.2.x/24` | 云台等自带 IP 的载荷，暂时空着 |

`.120` 避开了已被占用的 `.103` 与 `.105`。板子是 2.5G、机身多半是千兆，
会自动协商到 1000M，没有问题。

**eth0 不要配默认网关。** 机器狗内网没有互联网出口，配了会抢走默认路由，
之后想通过别的口上网就不通了，症状是"能 ping 通 IP 但域名解析不了"。

板子**没有板载无线**，平板链路需要另配 M.2 E-Key 模块，见
[rk3588-setup.md 阶段三](rk3588-setup.md)。

### 平板那侧：办公网段不能用 192.168.1.x

狗的地址是原厂固定的（`.103` / `.105`），2.4G 图传网卡在平板上也落在同一段，
所以**办公/现场的 WiFi 一定要换个网段**（例如 192.168.2.0/24），网关板的无线地址
跟着变，App 设置里改一下 MESH 地址即可。撞段的症状很像"WiFi 坏了"：

```
36: wlan0    inet 192.168.1.48/24
39: ar_net0  inet 192.168.1.11/24        ← 图传口，和 WiFi 同段
default via 192.168.1.1 dev ar_net0      ← 默认路由被图传口抢走
```

Android 把图传口当以太网、优先级高过 WiFi，于是 `ip route get <局域网地址>` 一律
返回 `ar_net0`：平板发给局域网的包、包括回给别人的 ping 应答，全从图传口出去。
切到 MESH 时射频是关的（`G20Rc.setBackupRadio`），那条路发不出去，于是"WiFi 显示
已连接，但谁也 ping 不通它"。2.4G 档反而通，因为射频开着，包绕无线电走了一圈 ——
往返 30 ms 以上就是这么来的（正常 WiFi 只有 1～3 ms）。

App 侧已经做了两件事兜底（`RadioLink`）：不再 `requestNetwork` 去帮图传口抢默认
网络；把进程默认出口钉在 WiFi 上（`pinProcess`），2.4G 用的 socket 各自按网卡绑。
但那只保住我们自己的连接，平板上其它 App 和"别人能不能 ping 通平板"仍要靠换网段。

## 四、在运动主机上登记本机

这一步不做的话，**收不到任何遥测**——运动主机只向登记过的地址单播。
网关会打印"未收到数据"，但指令仍然发得出去，很容易误判成"通了"。

```bash
ssh ysc@192.168.1.103          # 口令是一个单引号字符 '
vi /home/ysc/jy_exe/conf/network.toml
```

把本机 IP 与端口分别追加到两个数组，**索引必须一一对应**：

```toml
ip = '192.168.1.105'
target_port = 43897
local_port = 43893
ips   = ["192.168.1.105", "192.168.1.106", "192.168.1.120"]
ports = [43897,           43897,           43897]
```

然后重启运动程序：

```bash
cd ~/jy_exe/scripts && ./restart.sh
```

## 五、配置载荷参数

同样在运动主机上，改 `/home/ysc/jy_exe/conf/motion.toml`：

| 参数 | 含义 | 范围 |
| --- | --- | --- |
| `load` | 载荷质量 (kg) | 0.0 – 20.0 |
| `load_x` | 质心相对机体中心的纵向偏移 (m) | ±0.3 |
| `load_y` | 横向偏移 (m) | ±0.1 |
| `load_z` | 垂向偏移 (m) | 0.0 – 0.3 |

量级参考：智能控制器单独的标定值是 `load = 3.0, load_x = 0.05, load_y = 0.0, load_z = 0.10`。
按实际称重和实测质心位置填，别照抄。

**`enable_twist` 必须保持 false。** 手册明确警告带载荷开启会导致机器人摔倒。

`overtime.toml` 定义了断连后的降级顺序 `StopMotion` → `KeepStill` → `Sitdown`，
现场读一下具体秒数，网关的看门狗超时应当设得比 `StopMotion` 短，
这样正常情况下永远轮不到机器人自己降级。

## 六、跑通运动控制

```bash
cmake -S rk3588 -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j
./build/x30_gateway --robot-ip 192.168.1.103 --local-port 43897 --interactive
```

先敲 `s`。如果显示"未收到数据"，回到第四步检查 `network.toml`。

确认遥测正常后，按这个顺序验证。**第一次务必把机器狗架起来或在空旷处操作，
并让一个人守着遥控器上的软急停。**

```
s                  确认状态是「坐下」
stand              起立，等状态变成「初始站立」
torque             切「力控站立」
p 0 0 0.3 0        低头，验证姿态轴映射
p 0 0 0 0          回中
step               切「踏步」，机器人开始原地踏步
gait walk
v 0.2 0 0          缓慢前进，确认方向对
v 0 0 0.2          原地左转，确认转向符号对
freeze             停止喂数据，确认 2 秒内 vx 自己归零
step               停止踏步
stand              坐下
```

`freeze` 这一步是安全层验证，不要跳过。它模拟的是平板掉线，
必须看到速度自己降到零才说明看门狗生效了。

## 七、第 0 阶段：现场必须确认的事

这几项公开资料回答不了，会直接决定后续 SLAM 与视频模块的架构。
建议装机当天一次性验完。

### 1. 感知主机的 ROS 是否可达

手册全文没有 `ROS_MASTER_URI`、没有 ROS 发行版、没有 `.105` 的 SSH 口令。
在 RK3588 上试：

```bash
export ROS_MASTER_URI=http://192.168.1.105:11311
export ROS_IP=192.168.1.120
rostopic list
rostopic hz /lidar_points
rostopic hz /imu/data
```

同时确认 `.105` 的 Ubuntu 与 ROS 版本（`lsb_release -a`、`echo $ROS_DISTRO`），
大概率是 noetic / 20.04，但要实测。

**如果不可达**，退路是全部改走 UDP：运动数据已经能从 `.103` 拿到，
点云则需要研究 Livox 组播（Mid-360 的点云口 56300 与 IMU 口 56400 都支持组播），
但重配雷达会动到机器人自身的感知，风险高，属于下策。

### 2. `/lidar_points` 是不是四雷达的合并云，有没有逐点时间戳

API 文档只列了一条 `/lidar_points`（`sensor_msgs/PointCloud2`，10 Hz）和
一条 `/livox/lidar`（`CustomMsg`，10 Hz），没说是合并的还是轮流发的。

```bash
rostopic hz /lidar_points                    # 10Hz 还是 40Hz？
rostopic echo -n1 /livox/lidar | head -20    # 看 lidar_id 字段
rostopic echo -n1 /lidar_points --noarr      # 看 fields 里有没有时间戳
```

这决定 SLAM 前端怎么写：

- 若 `/lidar_points` 是合并云且**不含**逐点时间戳，就没法做扫描内运动畸变补偿，
  在四足这种剧烈晃动的载体上精度会明显变差，必须改订 `/livox/lidar` 的 `CustomMsg`
  （它带 `offset_time`）。
- `CustomMsg` 的消息定义需要 `source ~/jy_cog/transfer/setup.bash` 才能拿到，
  **但没有智能控制器就没有 `jy_cog` 目录**。所以要按 API 文档 §2.1 手工定义消息结构，
  或者从 `livox_ros_driver2` 上游仓库取。

### 3. 四个雷达的旋转外参

应用手册 §6.2 只给了平移（机体系，单位 mm）：

| 传感器 | X | Y | Z |
| --- | --- | --- | --- |
| 内置 IMU | 130.45 | −1 | 14.9 |
| 前向上雷达 | 443.67 | 0 | 54.15 |
| 前向下雷达 | 432.97 | 0 | −55.19 |
| 后向上雷达 | −465.76 | 0 | 34.84 |
| 后向下雷达 | −410.74 | 0 | −56.01 |

安装角度只有图，没有数值。四个雷达是前上/前下/后上/后下两组倾斜安装，
如果要自己合并点云，**必须先做外参标定**，可以用 TUMFTM/Multi_LiCa 这类无靶标方法。
标定完记得把 FAST-LIO2 的 `extrinsic_est_en` 设成 `false`，
在线估计在激励不足时会漂。

注意该表仅适用于整机版本 ≥401，现场核对铭牌。

### 4. 视频源

这是全案最大的未知。68 页 API 文档里 camera / image / video / rtsp 出现次数为零，
`/`+`rostopic list` 里也没有任何图像话题。装机时顺手确认：

```bash
rostopic list | grep -iE "image|camera|compressed"
nmap -p 554,8554,80,8080 192.168.1.0/24     # 看有没有设备开着 RTSP
```

同时向云深处售后明确索要"内置广角相机的取流接口文档"。
在拿到之前，方案按自加相机走，云台走它自己的 RTSP。

## 八、安全须知

- 操作时人与机器人保持 2 米以上距离。
- 机器人自身的运动学与地形感知一律不动。步态规划、落足点计算、避障
  继续由机器人负责，RK3588 只做网关与上层感知。
- RK3588 一旦成为心跳源，它就是新的单点故障。三层兜底缺一不可：
  平板断链 → 网关清零轴指令；网关宕机 → 机器人按 `overtime.toml` 降级；
  平板急停 → 直发 `0x21010C0E`，走独立通道，不排在视频队列后面。
- 楼梯步态必须配对应的地形图模式才生效，地形图模式在感知主机上设
  （UDP `192.168.1.105:43899` 或话题 `/height_map_mode`），不在运动主机。
- 匍匐档只支持 Walk 与缓坡步态，别在匍匐档切越野/楼梯/Run。

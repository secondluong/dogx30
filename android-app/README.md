# X30 遥控 App

平板端遥控应用。当前是网关自带控制台的原生壳，两端共用
`docs/app-protocol.md` 里的同一套 WebSocket 协议。

## 为什么先做壳

界面只有一处实现，改一次两端同时生效；而遥控逻辑里最容易出错的部分
（控制权、心跳、看门狗、切后台停车）也只需要验证一遍。

视频已经按这个思路走了一半：MESH 下仍是网页 WebRTC，而 2.4G 下必须原生
（狗只给 RTSP，WebView 放不了），画面垫在 WebView 底下，位置由网页报。
协议和控制逻辑一行没动。

原生壳相比直接用浏览器多做的事，都是浏览器给不了的：

- **屏幕常亮**。遥控时息屏等于失去控制。
- **锁横屏 + 拦截转屏重建**。Activity 重建会断开 WebSocket，机器狗随即停下。
- **返回键二次确认**。误触退出等于当场失控。
- **不先登录**。服务 IP 在设置里改；WiFi 不通也进遥控页，摇杆走已对频的 2.4G。
- **沉浸式全屏**。避免误触系统导航栏。
- **云卓 G20 通道**。L1/L2/摇杆不进 Android KeyEvent，必须走 RCSDK
  `KeyChannels` 轮询。通道表按现场量过的 CH 写死，直接当虚拟摇杆用。

## 构建

需要 JDK 17 与 Android SDK（compileSdk 34）。仓库里没有提交
`gradle-wrapper.jar`，首次构建先生成：

```bash
cd android-app
gradle wrapper --gradle-version 8.7
./gradlew assembleDebug
```

或直接用 Android Studio 打开 `android-app/` 目录。

产物在 `app/build/outputs/apk/debug/app-debug.apk`。

## 使用

1. 打开 App 即进遥控台（`/index.html?shell=app`）。默认连 `192.168.1.32:8080`。
2. 要改网关地址：点标题「X30 遥控台」→「本机连接网关」。网关不通时遮罩上也能改。
3. App 始终用包装里的页面。链路按钮在顶栏「急停」左边：MESH 走网关 WebSocket，2.4G 先开 G20 射频拉起 `192.168.144` USB 网，再把 `0x21` 发到 `192.168.1.103:43893`。串口数传通了也不算通。关云卓助手和云深处 App。
   顶栏芯片印 `包x.y.z 网页戳`，用来识破「网页资源是旧的」这种情况。
   网页资源由 `copyWebAssets` 在编译前自动从仓库 `web/` 拷进 `app/src/main/assets/web/`，
   所以**要在仓库里编，不要另存一份工程**。
4. 顶栏「背景」切换机身相机 / 布控白光 / 热成像 / 点云。选点云会自动订阅，切走就退订。
5. G20：先关掉云卓助手和其他地面站。左摇杆前后/侧走，右摇杆转向；
   L1 起立、L2 趴下、拍照截图（无屏幕按钮）、定位键按住说话、CH12 循环切背景、R1 显隐指标、
   CH13 急停、CH5 上拨摇杆控狗/下拨摇杆控布控球、
   滚轮下拨放大点云/上拨缩小（回中不回退）、R2 预留气体面板。
   原厂 2.4G 无线电手柄不经过平板。
6. App 选 MESH 时连上或回前台会自动接管。选 2.4G 时**运动指令**不经网关，
   但也不主动断网关：两条链路同时在时（平板既连 WiFi 又开 2.4G），
   遥测和布控球画面仍由网关下发。链路芯片会分开报 `2.4G通/断` 和 `网关通/断`。
   网页控制台仍用「控制权」。
7. **2.4G 下的画面**：这条链路是遥控器与狗直连，网关不在链路上（够不到它），
   所以机身相机由 App **原生拉狗身上的 RTSP**（默认
   `rtsp://192.168.1.105:8554/test`，在设置「2.4G 机身相机」里可改），
   画面垫在网页底下。布控球在网关那侧的网段，2.4G 到不了，那两格会如实标出来。
   没画面时占位图上直接写原因（地址不对 / 相机没起来 / 网卡没绑上各不相同），
   不用去翻日志。原理见 `docs/media-architecture.md` 第十一节。
8. **画面慢的时候**先看设置里「2.4G 机身相机」那行显示的本机缓冲毫秒数。
   播放器已按低延迟配（不攒点播那 2.5 秒、攒出来的会快放追掉、关掉音轨），
   所以这个数接近 0 时说明延迟在上游 —— 相机是 USB 转码出来的，链路也窄，
   那要去降相机码率/分辨率，调 App 没有用。

## 已知限制

- App 走 `?shell=app`：单张背景切换，不用一主三小/四宫格，虚拟摇杆交给实物手柄。网页控制台布局不变。
- G20 通道按现场实测写死。若在设备助手里改过通道表，这里会对不上。
- 版本戳从顶栏挪进了设置面板（顶栏是遥控时要盯的地方）。装包漏拷
  `assets/web` 时页面会是旧的，除了对这个戳没别的办法看出来。
- WebView 的触摸延迟比原生高十几毫秒。目前的速度控制回路能接受，
  若现场实测手感不足，再把摇杆改成原生控件、只保留数据面在 WebView 里。

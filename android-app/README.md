# X30 遥控 App

平板端遥控应用。当前是网关自带控制台的原生壳，两端共用
`docs/app-protocol.md` 里的同一套 WebSocket 协议。

## 为什么先做壳

界面只有一处实现，改一次两端同时生效；而遥控逻辑里最容易出错的部分
（控制权、心跳、看门狗、切后台停车）也只需要验证一遍。
后续视频与点云要上原生渲染时，把对应区域换成 `SurfaceView` 即可，
协议和控制逻辑不用动。

原生壳相比直接用浏览器多做的事，都是浏览器给不了的：

- **屏幕常亮**。遥控时息屏等于失去控制。
- **锁横屏 + 拦截转屏重建**。Activity 重建会断开 WebSocket，机器狗随即停下。
- **返回键二次确认**。误触退出等于当场失控。
- **不先登录**。服务 IP 在设置里改；WiFi 不通也进遥控页，摇杆走已对频的 2.4G。
- **沉浸式全屏**。避免误触系统导航栏。
- **云卓 G20 通道**。L1/L2/摇杆不进 Android KeyEvent，必须走 RCSDK
  `KeyChannels` 轮询。通道表按现场量过的 CH 写死，直接当虚拟摇杆用。

## 构建

需要 JDK 17 与 Android SDK（compileSdk 34）。仓库里没有提交
`gradle-wrapper.jar`，首次构建先生成：

```bash
cd android-app
gradle wrapper --gradle-version 8.7
./gradlew assembleDebug
```

或直接用 Android Studio 打开 `android-app/` 目录。

产物在 `app/build/outputs/apk/debug/app-debug.apk`。

## 使用

1. 打开 App 即进遥控台（`/index.html?shell=app`）。默认连 `192.168.1.32:8080`。
2. 要改网关地址：点标题「X30 遥控台」→「本机连接网关」。网关不通时遮罩上也能改。
3. 顶栏默认 MESH：画面和控制都走网关。不要开机就切 2.4G——上一版自动开数传会把 G20 画面掐掉。2.4G 只在网关实在连不上、并且你主动点了「2.4G」时才用。
4. 顶栏「背景」切换机身相机 / 布控白光 / 热成像 / 点云。选点云会自动订阅，切走就退订。
5. G20：先关掉云卓助手和其他地面站。左摇杆前后/侧走，右摇杆转向；
   L1 起立、L2 趴下、拍照截图（无屏幕按钮）、定位键按住说话、CH12 循环切背景、R1 显隐指标、
   CH13 急停、CH5 上拨摇杆控狗/下拨摇杆控布控球、
   滚轮下拨放大点云/上拨缩小（回中不回退）、R2 预留气体面板。
   原厂 2.4G 无线电手柄不经过平板。
6. App 选 MESH 时连上或回前台会自动接管。选 2.4G 时不经网关。网页控制台仍用「控制权」。

## 已知限制

- App 走 `?shell=app`：单张背景切换，不用一主三小/四宫格，虚拟摇杆交给实物手柄。网页控制台布局不变。
- G20 通道按现场实测写死。若在设备助手里改过通道表，这里会对不上。
- WebView 的触摸延迟比原生高十几毫秒。目前的速度控制回路能接受，
  若现场实测手感不足，再把摇杆改成原生控件、只保留数据面在 WebView 里。
